# LotWatch AI

**Supplier Quality Change Monitoring** — 규격 이내의 품질 변화까지 찾아내는 AI 품질 모니터링

COA 및 수입검사 데이터를 시간순으로 분석하여 규격 이탈 전 나타나는 품질 변화를 찾아내고, 확인이 필요한 Lot을 알려줍니다.

> "규격을 통과했더라도, 품질 데이터가 평소와 달라지고 있다면 알려드립니다."

---

## 1. 프로젝트 설명

LotWatch AI는 공급사의 **COA(시험성적서) 또는 수입검사 데이터**를 시간순으로 분석해서, 아래와 같은 경우 QC 담당자가 추가로 확인할 수 있도록 알려주는 품질 변화 모니터링 도구입니다.

- 모든 Lot이 **현재 규격에는 들어오지만**, 과거 데이터와 비교했을 때 품질 특성의 **평균이나 추세가 달라지고 있는 경우**
- **시험방법(Test Method)이 변경**된 경우
- 변화가 생긴 시점 전후로 **등록된 4M(Man, Machine, Material, Method) 변경 이력이 확인되지 않는 경우**

LotWatch AI는 공급사의 "미신고 변경"이나 "부정행위"를 **확정하는 서비스가 아닙니다.**
데이터에서 보이는 변화를 알려주고, "변화가 감지되었습니다", "확인이 필요합니다", "해당 기간 내 등록된 4M 변경 이력이 확인되지 않았습니다"처럼 **확인을 권고**합니다.
(4M 변경 이력이 없다는 것은 "등록된 기록이 없다"는 뜻이며, 실제로 변경이 없었다는 뜻이 아닙니다.)

## 2. 문제 정의

- 수입검사는 대부분 Lot별 **합격/불합격(규격 판정)** 만 확인합니다.
- 그래서 규격 안에서 조금씩 움직이는 변화(평균 이동, 드리프트)는 **불합격이 나오기 전까지 눈에 띄지 않습니다.**
- 공급사의 원료·설비·공정·시험방법(4M) 변경은 품질 변화의 주요 원인이지만, 변경 통보가 늦거나 누락될 수 있습니다.
- 결국 문제는 규격 이탈이나 고객 불만으로 드러난 뒤에야 발견되고, 그때부터 원인 추적이 시작됩니다.

LotWatch AI는 **"규격 부적합"과 "변화 감지"를 분리해서 보여주어**, 규격 이탈이 생기기 전에 공급사에 확인할 수 있게 돕습니다.

## 3. 핵심 기능

| 기능 | 설명 |
|---|---|
| 규격 판정 | Lot별 PASS / OUT OF SPEC 판정 (규격 최소값·최대값 직접 입력) |
| 추세 비교 | 초기 10 Lot 평균과 최근 10 Lot 평균, 전체 평균 비교 |
| 변화점 탐지 | 평균이 달라진 시점(Lot)을 자동으로 찾고, 변화 전/후 평균 비교 |
| 시험방법 변경 탐지 | Test_Method가 바뀐 시점 표시 (예: A → B, Lot 035부터) |
| 4M 변경 이력 비교 | 변화 시점 전후 N일(기본 30일) 안에 4M 변경 기록이 있는지 확인 |
| AI 품질 분석 | Google Gemini API가 통계 결과를 QC 담당자용 리포트로 정리 (API Key가 없거나 호출에 실패하면 통계 기반 기본 요약 리포트로 자동 대체) |
| 대시보드 | KPI, 추세 그래프(규격선·변화점·4M 표시), 상태별 색상, Lot별 판정표, 결과 CSV 다운로드 |

### 샘플 데이터 시나리오 (데모)

`샘플 데이터로 분석하기` 버튼을 누르면 A사 원료 40 Lot을 분석합니다.

- 40 Lot **모두 규격 통과** (Moisture ≤ 0.50, Purity ≥ 99.0)
- 하지만 **Lot 021부터 Moisture 평균이 0.144 → 0.269로 상승**하는 변화 감지
- **Lot 035부터 시험방법이 A → B로 변경**
- 4M 변경 이력(3월 정기 설비 점검, 7월 원료 공급처 변경)은 두 변화 시점과 30일 이상 떨어져 있어 **"해당 기간 내 등록된 4M 변경 이력이 확인되지 않았습니다. 공급사에 변경 여부 및 원인 확인을 권고합니다."**
- KPI: 총 Lot 40 · 규격 부적합 0 · **품질 변화 감지 1건 · 시험방법 변경 1건 · 확인 권고 2건**

## 4. 기술 스택

- **Python** 3.10 이상
- **Streamlit** — 웹 대시보드
- **Pandas / NumPy** — 데이터 처리
- **SciPy** — 통계 검정(Welch t-검정)
- **Plotly** — 추세 그래프
- **Google Gemini API** (`gemini-3.5-flash-lite`, 예비 `gemini-3.6-flash`, `google-genai` 패키지) — AI 품질 분석 리포트

## 5. 실행 방법

터미널(PowerShell 또는 명령 프롬프트)에서 아래 명령을 순서대로 입력합니다.

```bash
cd lotwatch-ai
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

- 브라우저가 자동으로 열리지 않으면 주소창에 `http://localhost:8501` 을 입력하세요.
- 종료할 때는 터미널에서 `Ctrl + C` 를 누릅니다.
- `streamlit run app.py` 도 되지만, Windows에서 "streamlit을 찾을 수 없습니다" 오류가 나면 위처럼 `python -m streamlit run app.py` 를 사용하세요.

**사용 순서**

1. `샘플 데이터로 분석하기` 버튼 → 바로 결과 확인
2. 내 데이터는 `COA CSV` 업로드 (4M 변경 이력 CSV는 선택) → 규격 입력 → `분석 시작`
3. 결과 화면에서 KPI → 추세 그래프 → 시험방법 변화 → 4M 비교 → AI 품질 분석 순서로 확인

## 6. CSV 형식

### COA CSV (필수)

| 컬럼 | 설명 | 예 |
|---|---|---|
| Lot | Lot 번호 | 001 |
| Date | 입고일 또는 시험일 | 2026-01-05 |
| Supplier | 공급사 | A사 |
| Moisture | 수분 (숫자) | 0.12 |
| Purity | 순도 (숫자) | 99.5 |
| Test_Method | 시험방법 | A |

```csv
Lot,Date,Supplier,Moisture,Purity,Test_Method
001,2026-01-05,A사,0.12,99.5,A
002,2026-01-12,A사,0.13,99.5,A
003,2026-01-19,A사,0.14,99.4,A
```

### 4M 변경 이력 CSV (선택)

| 컬럼 | 설명 | 예 |
|---|---|---|
| Date | 변경일 | 2026-05-01 |
| Type | 변경 유형 (Man / Machine·Equipment / Material / Method 등) | Equipment |
| Description | 변경 내용 | 생산설비 변경 |

```csv
Date,Type,Description
2026-05-01,Equipment,생산설비 변경
2026-06-15,Material,원료 공급처 변경
```

### 작성 규칙

- 날짜는 `2026-01-05` 형식을 권장합니다. (`2026/1/5`, `2026.01.05`도 읽을 수 있습니다.)
- Moisture, Purity에는 **숫자만** 입력합니다. (`<0.05`, `0.12%`처럼 기호가 있으면 오류 안내가 표시됩니다.)
- 엑셀에서 저장한 CSV(한글 포함)도 읽을 수 있습니다.
- COA는 **CSV 또는 Excel(.xlsx, 첫 번째 시트)** 로 올릴 수 있습니다.
- 공급사마다 다른 컬럼명을 자동으로 인식합니다. 대소문자·공백·괄호·`_`·`-` 차이는 무시합니다.
  - Lot: Lot No., Lot Number, Batch, Batch No., Batch Number
  - Date: Test Date, Inspection Date, 검사일, 시험일, 분석일
  - Supplier: Supplier Name, Vendor, 공급업체, 공급사
  - Moisture: Moisture (%), Water Content, 수분, 수분(%)
  - Purity: Purity (%), Assay, 순도, 순도(%)
  - Test_Method: Test Method, Method, 시험방법, 분석방법
- 업로드하면 인식 결과를 표로 먼저 보여주고, **이대로 분석하기**를 눌러야 분석합니다. 인식하지 못한 컬럼은 화면에서 원본 컬럼을 직접 선택할 수 있습니다.
- 한 파일에 여러 공급사가 섞여 있으면 **분석할 공급사를 선택**하는 메뉴가 나타납니다.
- 10 Lot 이상을 권장합니다. (8 Lot 미만이면 변화점 분석을 건너뜁니다.)
- 문제가 있으면 "CSV에 Date 컬럼이 필요합니다", "Date 형식을 확인해주세요 (확인할 행: 3)"처럼 **몇 번째 행을 고쳐야 하는지** 알려줍니다.

## 7. AI API 설정 방법

AI 품질 분석은 **Google Gemini API의 무료 사용량**으로 작동합니다. (Google 계정만 있으면 되고, 카드 등록이 필요 없습니다.)

1. [Google AI Studio](https://aistudio.google.com)에서 Gemini API Key를 발급합니다.
2. 아래 방법 중 **하나**로 Key를 설정합니다. 코드는 `st.secrets["GEMINI_API_KEY"]`에서만 Key를 읽습니다.

**방법 A — 내 컴퓨터에서 실행할 때**

`lotwatch-ai/.streamlit/secrets.toml` 파일에 한 줄을 적습니다.

```toml
GEMINI_API_KEY = "여기에-발급받은-키"
```

**방법 B — Streamlit Community Cloud에 배포한 경우**

앱 설정의 `Settings → Secrets`에 방법 A와 같은 내용을 붙여 넣습니다.

> ⚠️ API Key를 코드에 직접 적거나 GitHub에 올리지 마세요. `.gitignore`에 `.streamlit/secrets.toml`이 포함되어 있어 Git에는 올라가지 않습니다.

**동작 방식**

- 모델은 `gemini-3.5-flash-lite`(빠르고 무료 사용량이 많음)를 먼저 쓰고, 한도 초과·일시 장애가 나면 `gemini-3.6-flash`로 자동으로 다시 시도합니다. (`ai_report.py`의 `MODELS`에서 변경)
- 같은 분석 결과로 다시 요청하면 저장해 둔 리포트를 보여줘 무료 사용량을 아낍니다. (앱을 다시 시작하면 초기화)
- **API Key가 없거나, 호출이 실패하거나, 무료 사용 한도를 넘으면** 앱은 멈추지 않고 "AI 연결 실패로 기본 요약 리포트를 표시합니다."라는 안내와 함께 통계 분석 결과로 만든 기본 요약 리포트를 보여줍니다.
- API Key는 화면, 오류 메시지, 터미널 기록 어디에도 표시되지 않습니다.
- AI 리포트 끝에는 항상 "본 결과는 데이터 변화에 대한 확인 권고이며, 공급사의 변경이나 부적합을 확정하는 판단이 아닙니다."가 표시됩니다.

## 9. 분석 방법

### 규격 판정
`최소값 ≤ 측정값 ≤ 최대값`이면 **PASS**, 아니면 **OUT OF SPEC** 입니다. 대시보드에서는 "규격 부적합"과 "변화 감지"를 **따로** 보여줍니다.

### 추세 비교
초기 10 Lot 평균(기준)과 최근 10 Lot 평균, 전체 평균을 비교합니다. (Lot이 20개보다 적으면 절반씩 비교)

### 변화점 탐지 (Mean Shift)
1. 데이터를 "앞 구간"과 "뒤 구간"으로 나누는 모든 위치를 하나씩 시험합니다.
2. 두 구간을 각자의 평균으로 설명했을 때 남는 오차가 가장 작은 위치를 **변화점 후보**로 고릅니다.
   (ruptures 라이브러리의 L2 비용 변화점 탐지와 같은 원리를, 설치 문제 없이 이해하기 쉽게 직접 구현했습니다.)
3. 아래 두 조건을 **모두** 만족하면 "변화 감지"로 판단합니다.
   - 변화 전후 평균 차이가 **평소 변동폭(구간 안의 표준편차)의 1.5배 이상**
   - **Welch t-검정 p-value < 0.01** (우연히 생긴 차이일 가능성 1% 미만)
4. 변화 전/후 구간은 각각 최소 4 Lot이 필요합니다.

시뮬레이션 기준(40 Lot), 변화가 없는 데이터를 "변화 감지"로 잘못 판단할 확률은 약 1%입니다. 평소 변동폭의 2배 크기 변화는 변화 후 10 Lot 이상 쌓이면 약 90% 이상 감지합니다.

### 시험방법 변경 탐지
시간순으로 Test_Method 값을 비교해서, 값이 바뀐 첫 Lot을 표시합니다. (빈 값은 건너뜀)

### 4M 변경 이력 비교
변화 시점(변화 후 첫 Lot의 날짜) 전후 N일(기본 30일, 화면에서 7~90일 조정) 안에 4M 변경 기록이 있으면 "변화 시점과 근접한 4M 변경 이력이 있습니다", 없으면 "품질 변화가 감지되었으나 해당 기간 내 등록된 4M 변경 이력이 확인되지 않았습니다. 공급사에 변경 여부 및 원인 확인을 권고합니다."라고 표시합니다.

### 상태와 KPI

| 상태 | 의미 |
|---|---|
| 🟢 정상 | 규격 이내, 뚜렷한 변화 없음 |
| 🟡 주의 | 변화 감지, 변화 시점과 근접한 4M 변경 이력 있음 → 변경 내용과 품질 영향 확인 |
| 🟠 확인 필요 | 변화 감지, 해당 기간 내 등록된 4M 변경 이력 없음 → 공급사에 변경 여부 및 원인 확인 권고 |
| 🔴 규격 부적합 | 규격을 벗어난 Lot 있음 |

- **총 Lot**: 분석한 Lot 수
- **규격 부적합**: 규격을 벗어난 Lot 수
- **품질 변화 감지**: 평균이 통계적으로 달라진 품질 특성 수 (Moisture, Purity 각각 최대 1건)
- **시험방법 변경**: Test_Method 값이 바뀐 횟수 (예: A → B)
- **확인 권고**: 품질 변화·시험방법 변경 중, 변화 시점 전후로 등록된 4M 변경 이력이 확인되지 않은 건수

품질 변화(통계적 평균 변화)와 시험방법 변경은 성격이 달라서 KPI를 따로 표시합니다.

## 10. 한계점

- COA에 기록되지 않는 변경이나 측정되지 않은 불순물, 의도적인 데이터 조작 등을 확정적으로 탐지하는 시스템이 아니다.
- 통계적으로 "평소와 다르다"는 것을 알려줄 뿐, **원인이나 불량 여부를 판정하지 않습니다.** (변화 감지 ≠ 불량, 변화 감지 ≠ 미신고 변경)
- 품질 특성마다 **가장 뚜렷한 변화점 1개**만 찾습니다. 여러 번 바뀐 경우 일부 변화는 표시되지 않을 수 있습니다.
- 변화 전/후 구간에 최소 4 Lot이 필요하므로, **최근 3 Lot 이내에 시작된 변화는 데이터가 더 쌓여야** 감지됩니다.
- Lot 수가 적거나(10 Lot 미만) 측정값의 소수점 자리수가 적으면 작은 변화는 감지되지 않을 수 있습니다.
- 4M 비교는 **날짜가 가까운지만** 확인하며, 변경 내용과 품질 변화의 인과관계는 판단하지 않습니다.
- 현재는 Moisture, Purity 두 가지 품질 특성에 맞춰져 있습니다.
- AI 리포트는 통계 결과를 요약하는 보조 도구이므로 담당자의 검토가 필요합니다.
- AI 리포트는 Gemini API 무료 사용량으로 동작하므로, 한도를 넘으면 기본 요약 리포트로 대체됩니다. 무료 등급에 입력한 내용은 Google 제품 개선에 사용될 수 있으므로, 실제 기업의 기밀 COA 데이터에는 유료 등급이나 사내에서 승인된 AI 사용을 권장합니다.
- 분석 결과는 저장되지 않습니다. (새로고침하면 초기화)

## 11. 향후 확장 기능

- CSV의 모든 수치 컬럼을 품질 특성으로 자동 인식
- 여러 개의 변화점 탐지 (ruptures PELT 등), 산포(표준편차) 변화 탐지
- SPC 관리도 규칙(Western Electric Rules) 추가
- 공급사 COA 값과 자사 수입검사 값 비교 (COA 신뢰성 점검)
- PDF COA 자동 인식 (OCR + AI 추출)
- 공급사별 비교 대시보드, 분석 이력 저장
- 변화 감지 시 이메일/메신저 알림, PDF 리포트 출력
- ERP / LIMS 연동
